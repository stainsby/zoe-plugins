**Adopter notes.**

1. **What a session is.** *Terms* gains `session`: one run of the agent, with its own working
   context, on one conversation; your index says what counts as a conversation, and what ends
   a session.
   - *Terms*, `management session`: a session with no close on record is open, unless it has
     ended as your index provides. Only an open *management* session now stops other sessions
     doing management-grade writing (changing the enterprise's skills, plans, checks and
     records of its own running); before, any open session did.
   - `zoe-orient` step 7: the opening log entry names the conversation, where it named the
     channel.
   - `zoe-setup` asks, for each kind of record, whether several sessions will write it at
     once, and settles the index's new `sessions` line with the director.
   - The index template gains `sessions` — what counts as one conversation, what else ends a
     session, who is warned first, and whether a session ended that way counts as closed
     without a director's word — and `concurrency limit` now asks how long each worker may
     run.

   **What to do:** with your director, add a `sessions` line to your index — for a director's
   own sittings, "a sitting; ends on their word" — and add to `concurrency limit` how long each
   worker may run. On a shared chat channel, decide what counts as one conversation (a thread,
   say) and what ends a session. Where more than one session can be open at once, a management
   session may now change skills, the index and other records while a work session is still
   running, and both may write to the same records: ask your director, for each kind of
   record, whether several sessions will write it at once, and record the answer in your
   index. If an own skill writes the opening entry naming the channel, send it to
   `zoe-redesign` to name the conversation, unless the two are the same for you. Compare
   first: *Terms* (`session`, `management session`), `zoe-orient` step 7, `zoe-setup`'s
   storage question and its `sessions` line, and the index template's `sessions` and
   `concurrency limit` lines.
2. **Keeping the index's record of where things are current is not a skill change.** *Terms*,
   `index`: the index is kept as a skill; keeping its record of where things are current, as
   they are made, moved or removed, is not counted as a skill change, and is not gated unless
   specifically required. Changing one of the index's settings is not covered, and stays under
   whatever rule covers changes to your skills.
   **What to do:** if your own skills or charter treat every edit to the index as a skill
   change, or gate it, decide with your director whether that is still meant.
3. **The diet.** Sixty-two passages shortened or removed across the instructions, ten skills'
   `SKILL.md` and the index template. Most were a rule stated twice — a skill restating the
   instructions every session already loads, `zoe-setup` restating the templates it reads, a
   skill restating its own description — now stated once; the rest were reasons and asides
   beside rules that are complete without them. `zoe-setup` no longer suggests where the
   charter should live. The most shortened, by words removed: the instructions, `zoe-setup`,
   `zoe-reskill`, the index template, `zoe-redesign`, `zoe-upgrade` and `zoe-assess`; compare
   those first.
   **What to do:** if an own skill of yours quotes or cites a kernel sentence, re-read it
   against the new wording, and send any that no longer fits to `zoe-redesign`. The index
   template's opening lost "Fill in each line as you set that thing up."; you may drop it from
   your index. Several placeholders are shorter; the only field added is note 1's `sessions`,
   and none was removed or renamed.
4. **Outside the kernel: the plugin is enabled in one project.** The Claude plugin README's
   enable step is now `claude plugin enable zoe-kernel@zoe --scope project`, run from the root
   folder of the project that is to become the enterprise. As printed before, it enabled ZOE's
   skills and agents for the whole user account, so in every project.
   **What to do:** if you enabled it that way, run `claude plugin disable zoe-kernel@zoe --scope
   user`, then the new enable step from the root folder of each project that is an enterprise.
