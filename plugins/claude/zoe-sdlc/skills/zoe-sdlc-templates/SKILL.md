## A template is two things at once

It is the shape of the document it produces, and the instructions for producing
it: its sections carry guidance, questions to answer and placeholders alongside
the structure. Following the template *is* following the process, and skipping
a section that is not marked optional is skipping a step of it.

What form a template takes is the project's own choice — a file to copy, a form
in a tracker, a template in a document system. What matters is that the
guidance travels with the shape, in one piece.

## Using one

- **Copy the template exactly** to start a new document. Never rewrite its
  structure from memory: memory drops sections, and a dropped section is a step
  quietly skipped.
- **Read the whole thing before filling any of it in**, then fill it in one
  section at a time, following each section's own instructions.
- **Delete the guidance that was only there to tell you how to fill a section
  in.** Guidance meant to steer later edits stays.
- **A template that gets in the way is telling you something.** Propose a
  change to it, rather than filling a section in badly or leaving it out.

## Changing them

Each template records the one it was based on. A new template starts from the
most specific existing template that still fits, falling back to the most
general one the project holds if none does. Changing a template means looking
at the ones based on it; deleting one means updating them. Template work runs
under a task like any other work.
